HEALTHSAFE
STAGE 1-3 TEST RUN GUIDE
========================

Run these commands from the repository root.

  cd ~/Desktop/sin-000-healthsafe


1. RUN AUTOMATED TESTS
----------------------

  for service in alert-level-service ingestion-service staffing-service ward-service; do
    echo "Testing $service"
    (cd "$service" && mvn clean test) || exit 1
  done

Every service should finish with: BUILD SUCCESS


2. BUILD THE SERVICES
---------------------

  for service in ingestion-service ward-service alert-level-service staffing-service; do
    (cd "$service" && mvn package) || exit 1
  done


3. START ACTIVEMQ FOR STAGE 3
-----------------------------

  cd ~/Desktop/sin-000-healthsafe/common
  docker compose up -d
  docker compose ps

The ActiveMQ container should be running.

If Docker reports that it cannot connect to the Docker daemon, start Docker
Desktop first, then run the three commands again.


4. START THE SERVICES
---------------------

Open four terminal windows.

Terminal 1 - ingestion service:

  cd ~/Desktop/sin-000-healthsafe/ingestion-service
  java -jar target/ingestion-service.jar

Terminal 2 - ward service:

  cd ~/Desktop/sin-000-healthsafe/ward-service
  java -jar target/ward-service.jar

Terminal 3 - alert-level service:

  cd ~/Desktop/sin-000-healthsafe/alert-level-service
  java -jar target/alert-level-service.jar

Terminal 4 - staffing service:

  cd ~/Desktop/sin-000-healthsafe/staffing-service
  java -jar target/staffing-service.jar


5. STAGE 1 - INGESTION CHECKS
-----------------------------

  curl http://localhost:7030/health
  curl -s http://localhost:7030/wards | jq .
  curl -s http://localhost:7030/wards/w-05 | jq .
  curl -i http://localhost:7030/wards/does-not-exist

Expected:
  - /health returns OK.
  - /wards returns cleaned records.
  - w-05 is found case-insensitively.
  - An unknown ward returns HTTP 404.


6. STAGE 2 - REST SERVICE CHECKS
--------------------------------

Health checks:

  curl http://localhost:7031/health
  curl http://localhost:7032/health
  curl http://localhost:7033/health

Ward lookup:

  curl -s http://localhost:7031/wards | jq .
  curl -s http://localhost:7031/wards/W-01 | jq .
  curl -i http://localhost:7031/wards/unknown

Alert-level validation:

  curl -s http://localhost:7032/alert-level | jq .

  curl -s -X POST http://localhost:7032/alert-level \
    -H 'Content-Type: application/json' \
    -d '{"level":4}' | jq .

  curl -i -X POST http://localhost:7032/alert-level \
    -H 'Content-Type: application/json' \
    -d '{"level":9}'

The invalid alert level should return HTTP 400.

Staffing integration:

  curl -s -X POST http://localhost:7033/schedule/W-01 | jq .
  curl -s http://localhost:7033/schedule/W-01 | jq .
  curl -i http://localhost:7033/schedule/unknown

The schedule should include the ward, department, alert level, and on-call
doctor count. With alert level 4, onCallDoctors should be 5.


7. STAGE 3 - ACTIVEMQ TOPIC CHECK
----------------------------------

Set alert level 1 and create a schedule:

  curl -s -X POST http://localhost:7032/alert-level \
    -H 'Content-Type: application/json' \
    -d '{"level":1}' | jq .

  curl -s -X POST http://localhost:7033/schedule/W-01 | jq .

Check that ward-service received the asynchronous event:

  curl -s http://localhost:7031/wards/W-01/staffing | jq .

Change the alert level and publish another schedule update:

  curl -s -X POST http://localhost:7032/alert-level \
    -H 'Content-Type: application/json' \
    -d '{"level":6}' | jq .

  curl -s -X POST http://localhost:7033/schedule/W-01 | jq .
  curl -s http://localhost:7031/wards/W-01/staffing | jq .

The final response should show alertLevel 6 and onCallDoctors 7.

This confirms the Stage 3 flow:

  staffing-service -> ActiveMQ staffing-events-topic -> ward-service


QUICK STOP COMMANDS
-------------------

Stop the running Java services with Ctrl+C in each service terminal.

Stop ActiveMQ:

  cd ~/Desktop/sin-000-healthsafe/common
  docker compose down
